# Review: game-server functions part 1 (startup, network, character, combat-magic, items) and mechanics.md

Reviewer: read-only verification against v2.20 HGserver source (`.claude/scratch/srv220/`, Game.cpp unless stated).
Active build: GlobalDef.h defines DEF_CHINESE, which turns on DEF_V219, DEF_BEGINNERTOWNPROTECT, DEF_CHINESEGUILDLIMIT, DEF_NPCITEM, DEF_DBGAMESERVER, DEF_LOGTIME, DEF_DEFENCEHACKING. Inactive: DEF_TAIWANLOG, DEF_TESTSERVER, DEF_ITEMDROP, DEF_PKPENALTY, DEF_ALLPLAYERPROTECT, DEF_GUILDWARMODE, DEF_MAXLEVEL150, DEF_BEGINNEREVENTMODE.
Method: line ranges and brace ends checked by script for all 205 headings; callees, callers, message types and cfg literals diffed by script; every flagged item then read by hand. Severity: wrong / imprecise / missing.

Global notes (apply to many entries, not repeated per row):
- G1 (imprecise) The `cfg:` field is not a literal file read. Most entries list cfg files the body never opens (script check: CGame ctor, bInit, Quit, UseItemHandler, iCalculateUseSkillItemEffect, UseSkillHandler, ReqCreatePortionHandler, BuildItemHandler, _bCheckDupItemID, bGetItemNameWhenDeleteNpc, etc.). The header should say it means "data loaded from that config", otherwise readers assume a file open.
- G2 (imprecise) Call lists truncated with "..." are fine; the lists never contradicted the code except where listed below.
- G3 (imprecise) `_bItemLog` callees are inside inactive DEF_TAIWANLOG blocks (so not compiled) in: TrainSkillResponse 25421, RequestStudyMagicHandler 24961, RequestCivilRightHandler 27569, RequestPurchaseItemHandler 17089, both bSetItemToBankItem (27961, 32507), ReqRepairItemCofirmHandler 34585 (typo'd `#ifdef TAIWANLOG`), BuildItemHandler 43755, iCalculateAttackEffect 13733, ServerStockMsgHandler 49598. Only the headings of the _bItemLog overloads say "inactive"; callers do not.
- G4 (imprecise) Message lists: items.md entries list `DEF_OBJECTNULLACTION`/`DEF_OBJECTMOTION_CONFIRM`/`DEF_OBJECTDYING` that the body does not send (DropItemHandler lacks DEF_NOTIFY_DROPITEMFIN_*, ITEMRELEASED; GetItem lacks ITEMOBTAINED/CANNOTCARRYMOREITEM; Purchase lacks ITEMPURCHASED/NOTENOUGHGOLD; Sell/Repair lack SELLITEMPRICE/REPAIRITEMPRICE; Fish functions lack FISH* notices). Lists are partial, not wrong, but the `OBJECTNULLACTION` ones do not occur in ReleaseItemHandler, UseItemHandler, GiveItemHandler, bEquipItemHandler.
