# Review: research/shared (messages/*.md and formats/*.md)

Method: read-only. For the catalogue I wrote independent scripts (`.claude/scratch/review/check_msgs*.py`, `chk3.py`,
`chk7.py`, `chk8.py`) that re-parse every row and compare it with the raw `NetMessages.h` files (client
`sources/client-2.20`, server `.claude/scratch/srv220`, gate `0b994cd` (identical to `shared-ref/gate219`), 2.03
`shared-ref/srv203`) and the `.cpp` files; they do not reuse `gen_messages.py`. Formats were checked by reading the cited
lines, counting keys in the sample files and reading the sample bytes. Severity: wrong / imprecise / missing as in gate.md.
Nothing was run except the checking scripts.

## A. Message catalogue (messages/*.md): all 390 rows

Result of the mechanical checks, all clean:

- Hex value: every row's value equals the header value in every header listed in its Ver column (0 conflicts); every name in the four headers has a row (390 = 139 MSGID + 251 sub-types, no duplicates, none missing); the per-header counts 374 / 377 / 340 / 334 and per-file row counts (230, 37, 51, 17, 18, 10, 6, 21) are exact. No `MSGID_*` appears in any `.cpp`/`.h` of the four trees without a header definition.
- Ver column: no row lists a header that does not define the name, and none omits a header that does.
- Citations: all **1693** `file:line` citations exist, the line contains the name as a whole word, every `case` tag is a `case NAME` label and no `ref` tag is a case label.
- Hit counts: with `//` comments removed, the listed hits plus every `(+n)` equal the true number of lines containing the name, for all four code columns of all 390 rows (see S2 for what "comments excluded" really means).
- Official column: all 44 `official-*.md:N` cites point at a line containing the name and its hex; Docs column equals the exact set of `research/servers/*.md` files containing the name for all 390 rows.
- Official-doc tables elsewhere: 87 name/hex pairs in `official-mainserver.md`, `official-worldserver.md`, `official-compat-220.md` match the headers (0 mismatches); the only IDs not in any header are the WLS-only `0x0512A3E3` and `0x13000000`.

## B. Format docs (formats/*.md)

Checked: every citation in `amd-map.md`, `mapdata-txt.md`, `client-files.md`, `server-content-cfg.md`, `server-program-cfg.md`, `persistence-files.md` that names a function, key or line, against the cited source; the 25 key counts of `mapdata-txt.md` against `srv220/mapdata/*.txt` (59 files); the `.amd` sizes and counts; the field counts of the cfg decoders.

Requested claims:

- **Potion keyword**: `srv220/Game.cpp:38713` is `if (memcmp(token, "potion", 5) == 0)` - five bytes, i.e. `potio`. `srv220/portion.cfg` has 14 records, all starting `portion` (0 start with `potion`), and the file contains no other keyword path (`grep '"portion"'` in all `.cpp`: 0 hits). The claim is **verified**; the sample as shipped would load no potion records.
- **.amd index bug**: the expression `m_pTile + ix + iy*m_sSizeY` is at `srv220/Map.cpp:480`, **not 477** (477 is the `for (iy ...)` line; 479 is the `ReadFile`). The bug is real: it is also repeated at 694 and 702. See F1.
